network proxy是啥
0 tool calls · completed

network proxy 就是“网络代理”。

它的作用是让你的电脑先把网络请求发给一个代理服务器，再由代理服务器去访问外网。常见用途是：

  • 统一公司/校园网出口
  • 访问被限制的内网资源
  • 做缓存、审计、过滤
  • 让某些程序走指定网络路径

一般有这些类型：

  • HTTP proxy：给网页和多数 HTTP 请求用
  • HTTPS proxy：给加密网页请求用
  • SOCKS proxy：更通用，很多程序都能用
  • Auto / PAC：自动配置代理规则
  • None：不使用代理

和你刚才说的静态 IP 不一样：

  • 静态 IP 是给网卡固定一个本机地址
  • Proxy 是给“上网流量”加一层中转

如果你只是想让雷达网卡和设备直连，通常 network proxy 不用管，保持关闭就行。

ifconfig -a | grep can

cd ~/venom_ws
source install/setup.bash
ros2 launch scout_base scout_mini_base.launch.py

ros2 launch scout_base scout_mini_omni_base.launch.py

ros2 run teleop_twist_keyboard teleop_twist_keyboard

那就对上了。

如果小车没开机，CAN 总线通常不会正常工作，很多情况下 can0 也不会出现，或者即使接口出来了也不会有底盘数据。你现在这条报错更像是设备还没被底盘侧供电/识别。

你可以这样理解：

  • can0 先得有硬件接口
  • 小车上电 后，CAN-USB 适配器和底盘控制器才可能真正连通
  • 车没开时，candump can0 通常也看不到底盘数据

建议顺序是：

# 先把小车上电
sudo modprobe gs_usb
ip link | grep can
sudo ip link set can0 up type can bitrate 500000
candump can0

这个页面讲的是 simulation/venom_nav_simulation 这个独立仿真工作区，主要用来跑：

  • MID-360 + IMU 的仿真
  • Point-LIO 或 Fast-LIO
  • Nav2 建图和导航

按页面里的“快速开始”，最直接的本地跑法是：

cd simulation/venom_nav_simulation
rosdep install -r --from-paths src --ignore-src --rosdistro $ROS_DISTRO -y
colcon build --symlink-install
source install/setup.bash
ros2 launch rm_nav_bringup bringup_sim.launch.py \
  world:=RMUL \
  mode:=nav \
  lio:=pointlio \
  localization:=slam_toolbox \
  lio_rviz:=False \
  nav_rviz:=True

这几个参数的意思大致是：

  • world:=RMUL：加载 RMUL 仿真场景
  • mode:=nav：进入导航模式
  • lio:=pointlio：用 Point-LIO
  • localization:=slam_toolbox：用 slam_toolbox 做定位/建图
  • lio_rviz:=False、nav_rviz:=True：只开导航相关 RViz

如果你想走 Docker，页面也给了统一环境：

cd ~/venom_ws/src/venom_vnv
make build
make up
make shell

进容器后再执行 rosdep 和 colcon build。

这个仿真工作区本质上是给你在真车前先把“建图 -> 定位 -> 导航”链路跑通。来源页在这里：
导航仿真工作区

如果你要，我可以继续按这页给你拆成“本机安装版”和“Docker版”两套一步一步命令。
