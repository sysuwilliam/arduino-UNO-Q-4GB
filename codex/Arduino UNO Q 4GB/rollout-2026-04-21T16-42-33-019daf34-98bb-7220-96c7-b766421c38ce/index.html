App.run(user_loop=loop)什么意思
0 tool calls · completed

App.run(user_loop=loop) 的意思是：启动 Arduino App Lab 的 Python 应用运行时，并把你定义的 loop 函数注册成“反复执行的主循环”。

结合你前面那个 Blink 例程来看，它等价于告诉系统：

  • 启动这个 App
  • 初始化 App Lab 运行环境、Bridge 等工具
  • 然后不断调用 loop() 这个函数

所以在这个例程里：

def loop():
    global led_state
    time.sleep(1)
    led_state = not led_state
    Bridge.call("set_led_state", led_state)

App.run(user_loop=loop)

实际效果就是： 1. App 启动。 2. 系统不断执行 loop()。 3. 每次 loop() 先等 1 秒。 4. 然后切换一次 led_state。 5. 再通过 Bridge.call() 通知 Arduino 改变 LED 状态。

如果不写 user_loop=loop，只写：

App.run()

那就只是启动 App 运行时，本身不会自动反复执行你这个自定义循环函数。这种写法更适合像天气项目那样“等 Arduino 来调用 Python 函数”的场景。

你可以简单记成：

  • App.run()：启动 App
  • App.run(user_loop=loop)：启动 App，并持续执行 loop() 这个用户循环

参考位置： Blink 注释版 main.py 官方入门指南

那我可以说在loop函数中，while true:...达到同样的效果吗
0 tool calls · completed

可以达到“反复执行”的效果，但不完全等价，不建议这么写。

如果你在 loop() 里再套一个：

def loop():
    while True:
        ...

那效果会变成：

  • App.run(user_loop=loop) 调用一次 loop()
  • 这个 loop() 里面自己就死循环了
  • 运行时拿不到控制权去正常调度下一轮

而官方推荐的写法是：

def loop():
    ...
    ...

App.run(user_loop=loop)

意思是：

  • App 运行时负责一轮一轮调用 loop()
  • loop() 自己只做“一次循环该做的事”
  • 不要在里面再套无限循环

你可以这样理解：

  • App.run(user_loop=loop) 已经帮你提供了外层循环
  • loop() 里再写 while True，就相当于又套了一层死循环

所以结论是：

  • “看起来会一直跑”这点相似
  • 但设计上不一样
  • 在 user_loop 模式下，通常不要在 loop() 里再写 while True

对比一下更清楚：

推荐：

def loop():
    time.sleep(1)
    do_something()

App.run(user_loop=loop)

不推荐：

def loop():
    while True:
        time.sleep(1)
        do_something()

App.run(user_loop=loop)

第二种会让 App.run() 只进入一次 loop()，之后就被你自己的死循环卡住了。

你可以把它简单理解成：

  • Arduino 平台专用的主程序文件

  • 里面通常写硬件控制逻辑

void setup() {
}

void loop() {
}

  • setup()：上电后执行一次，用来做初始化

在你前面看的项目里：

  • Python 的 main.py 跑在 UNO Q 的 Linux 系统一侧
  • .ino 文件跑在微控制器一侧
  • 它更适合写 GPIO、LED、传感器、串口这类底层硬件控制代码

比如这个文件就是 .ino： sketch.ino

所以一句话说：

.ino = Arduino 程序主文件 = Arduino 风格的 C++ 源文件

所以call是发送，provide是接收吗
0 tool calls · completed

可以这么粗略理解，但更准确一点：

  • provide：把一个函数“注册出来”，让对方可以调用
  • call：去调用对方已经注册好的函数

所以它们不是单纯的“发送/接收”，而是“提供服务 / 调用服务”。

拿你前面的例子说：

Arduino 这边：

Bridge.provide("set_led_state", set_led_state);

意思是： “我这里提供一个叫 set_led_state 的接口，你别的一端可以来调我。”

Python 这边：

Bridge.call("set_led_state", led_state)

意思是： “我现在去调用你提供的 set_led_state，并把 led_state 这个参数传过去。”

所以关系更像：

  • provide = 开一个可调用接口
  • call = 调这个接口

如果你非要对应“发送/接收”去记，也可以暂时记成：

  • call 更像主动发起请求
  • provide 更像提前准备好接收调用

但最好记成“注册接口”和“调用接口”，这样更准确。

这样写 i 不会累计。

原因和你刚才 .ino 里那个 int i = 1; 一样：

def loop():
    i = 0
    ...
    i += 1

每次进入 loop() 时，i 都重新变成 0，然后加 1，所以你每次打印出来都会是：

True 1
False 1
True 1
False 1

也就是说：

  • led_state 会正常翻转
  • 但 i 永远都是 1

如果你想让 i 真正累计，要把它放到函数外面，像这样：

from arduino.app_utils import *
import time

led_state = False
i = 0

def loop():
    global led_state, i
    time.sleep(0.2)
    led_state = not led_state
    i += 1
    print(led_state, i)
    Bridge.call("set_led_state", led_state)

App.run(user_loop=loop)

这样效果就是：

  • 第一次打印：True 1
  • 第二次打印：False 2
  • 第三次打印：True 3
  • 第四次打印：False 4

因为这时 i 是全局变量，不会每次进入 loop() 都重置。

一句话总结：

  • 写在 loop() 里面：每次重新初始化
  • 写在 loop() 外面：才能跨多次循环累计

这个报错说明：

你在 loop() 里写了 i += 1，Python 把 i 认定为局部变量，但这个局部变量在当前函数里还没有先赋值，所以报错了。

核心原因是这类代码：

i = 0

def loop():
    i += 1

在 Python 看来：

  • 因为你写了 i += 1
  • 所以 i 被当成 loop() 里的局部变量
  • 但局部变量 i 在执行 i += 1 前并没有值
  • 所以报 UnboundLocalError

正确写法有两种。

第一种，用全局变量：

from arduino.app_utils import *
import time

led_state = False
i = 0

def loop():
    global led_state, i
    time.sleep(0.2)
    led_state = not led_state
    i += 1
    print(led_state, i)
    Bridge.call("set_led_state", led_state)

App.run(user_loop=loop)

这里 global i 的意思是： “我在这个函数里操作的不是新的局部变量，而是外面的全局变量 i。”

第二种，不用全局变量，而是每次都在函数里重新定义：

def loop():
    i = 0
    i += 1

这不会报错，但每次结果都还是 1，因为它不会累计。

所以你现在想要“计数递增”，就应该用第一种。

一句话概括这次报错：

i += 1 让 Python 认为 i 是局部变量，但你又没先在函数里给这个局部变量赋初值。

报错原因很直接：Monitor.print() 不是 printf()，它不支持这种格式化写法：

Monitor.print("%d\n", i);

你把它当成 C 语言的 printf("%d\n", i) 在用了，但 Arduino 这套 Print 接口不是这么设计的。

正确写法是分开写。

如果你只是想输出数字：

Monitor.print(i);

如果你想输出后换行：

Monitor.println(i);

所以你这里应该改成：

void set_led_state(bool state) {
    static int i = 1;
    digitalWrite(LED_BUILTIN, state ? LOW : HIGH);
    Monitor.println(i);
    i++;
}

如果你想带文字一起输出，也要拆开：

Monitor.print("i = ");
Monitor.println(i);

或者：

Monitor.print("count: ");
Monitor.println(i);

一句话区分：

适合： - 已知循环次数 - 遍历列表、字符串等

while True:
    print("一直执行")

这个会一直跑，通常要配合条件跳出或 break。

4. 跳出循环

while True:
    x = 3
    if x == 3:
        break

break 表示立刻结束循环。

5. 跳过本轮

for i in range(5):
    if i == 2:
        continue
    print(i)

会跳过 2，输出： 0 1 3 4

  • 第 2 帧显示一段时间
  • 第 3 帧显示一段时间
  • 播放完这组序列后结束

{0x04812805, 0x80138390, 0x03402902, 0x40000000, 500}

最后的 500 就表示这一帧显示 500ms。

所以：

  • loadSequence(...)：加载一整组帧
  • playSequence()：把这组帧按顺序播放一遍
  • playRepeat(n)：把这一遍重复 n 次

一句话：

playSequence() 就是逐帧播放当前序列的一次完整动画。
