#### 理解权限

默认情况下，Linux 上的 USB 设备仅可由 root 用户或特定组中的用户访问。当 UNO Q 连接到您的计算机时，它会创建 USB 设备文件，通常位于以下目录：

```

# Arduino UNO Q 4GB 开发板介绍

## 一、基本外观

Arduino UNO Q是一块小巧漂亮的开发板，集成了高通的MPU和STM32的MCU，下面来看看这块开发版的结构和功能：

![UNO 外形规格](https://docs.arduino.cc/static/7d5a122fd16435d60983ecb96c2e490f/a6d36/uno-form-factor.png)

### 板载 LED 矩阵

这块板子的一个特点是板载 **8×13 蓝色 LED 矩阵**，支持 **8 级灰度**，可实现渐变效果,由 STM32 微控制器管理。看着挺规整，不过这么多的区域放LED阵列感觉会有些冗余，如果换成板载LCD应该会更舒服。

![LED 矩阵](https://docs.arduino.cc/static/66bc34d048f9376836e3520a1ad2553d/a6d36/matrix.png)

### 四个 RGB LED

UNO Q 配备 **4 个 RGB LED**，可以显示开发板状态或通过程序控制：
- **LED 1 & 2**：由高通 MPU控制
- **LED 3 & 4**：由 STM32 MCU控制

![UNO Q RGB LED](https://docs.arduino.cc/static/10826219b80fd6d653c4601862558c1e/a6d36/rgb-led.png)

发现这里使用不同的处理器控制不同的外设，体现了双处理器架构的特点。

### 电源按钮

开发板配备物理电源按钮，**长按 5 秒以上**可重启 Linux 系统。

![UNO Q 电源按钮](https://docs.arduino.cc/static/992b8761457e587a6843b49ba732d1b4/a6d36/power-button.png)

大概率不是“从 Arduino App Lab 导出到本机”，而是把 板子上的 App 目录 拷到你的文件夹里。

我查到的当前资料里，Arduino 官方 arduino-app-cli 说明用户创建的 Apps 默认保存在板子上的 /home/arduino/ArduinoApps，持久数据在每个 App 目录下的 data/，运行缓存通常在 .cache/。官方 App Lab 文档页也明确把 Arduino App CLI 和 Manage Apps 作为标准能力。基于这点，我判断你在 App Lab 里创建的工程，通常就在 UNO Q 的 Linux 文件系统里，而不一定在你电脑当前这个仓库里。

最直接的做法是用 scp 复制到你的本地文件夹：

scp -r arduino@<开发板IP>:/home/arduino/ArduinoApps/<你的App名字> "/你的目标文件夹/"

如果你想复制到你现在这个仓库里，例如：

scp -r arduino@192.168.1.50:/home/arduino/ArduinoApps/my-app "/home/william/Desktop/Arduino UNO Q 4GB/"

也可以先 SSH 上板子确认目录：

ssh arduino@<开发板IP>
ls -la /home/arduino/ArduinoApps

如果你是在 UNO Q 的 SBC 模式里直接本机操作，那就不用 scp，直接在板子上复制：

cp -r /home/arduino/ArduinoApps/<你的App名字> /你想放的目录/

注意两点： - data/ 里通常是你 App 的持久化数据，复制时建议一起带走。 - .cache/ 多半是运行缓存和环境文件，通常不是必须；如果你只想备份源码，可以复制后把 .cache/ 删掉。

参考： - Arduino App Lab 总入口: https://docs.arduino.cc/software/app-lab/ - 官方 arduino-app-cli 仓库，对 Apps 默认目录有说明: https://github.com/arduino/arduino-app-cli
