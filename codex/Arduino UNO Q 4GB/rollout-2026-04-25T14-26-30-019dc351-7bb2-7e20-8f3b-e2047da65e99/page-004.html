-# 😀 LED_showtext
-
-`LED_showtext` is an Arduino App Lab example for **Arduino UNO Q** that scrolls
-text across the onboard **8 x 13 LED matrix**.
-
-The App uses a split architecture:
-
-- `python/main.py` runs on the Linux side of UNO Q and watches a text file.
-- `sketch/sketch.ino` runs on the MCU side and renders scrolling text on the LED matrix.
-- The two sides communicate through `Arduino_RouterBridge`.
-
-## How It Works
-
-The text update pipeline is:
-
-1. Python reads `python/led_text.txt`.
-2. If the file content changed, Python calls `Bridge.call("set_text", text)`.
-3. The sketch receives the new string through `setText(...)`.
-4. The sketch redraws the LED matrix and keeps replaying the scroll animation in `loop()`.
-
-This design avoids hardcoding the text in the sketch and makes updates possible
-without editing or recompiling the Arduino code each time.
-
-## Project Structure
-
-```text
-led_showtext/
-├── app.yaml                 # App metadata
-├── python/
-│   ├── main.py              # Linux-side controller
-│   └── led_text.txt         # Source text to display
-└── sketch/
-    ├── sketch.ino           # MCU-side LED matrix rendering
-    └── sketch.yaml          # Sketch platform and library dependencies
-```
-
-## Main Files
-
-### `python/main.py`
-
-Responsibilities:
-
-- Poll `python/led_text.txt`
-- Detect when the content changes
-- Send the updated string to the sketch using RouterBridge
-
-Important details:
-
-- Polling interval is controlled by `POLL_INTERVAL_SEC`
-- Empty text is ignored
-- Previously sent text is cached so unchanged content is not resent
-
-### `sketch/sketch.ino`
-
-Responsibilities:
-
-- Initialize the UNO Q LED matrix
-- Register the `set_text` RPC endpoint
-- Render scrolling text with `ArduinoGraphics`
-- Replay the current scroll animation continuously
-
-Important details:
-
-- Uses `Font_5x7`, which fits the 8x13 matrix reasonably well
-- Uses `SCROLL_LEFT` for leftward scrolling
-- Starts with a blank display until Python pushes the first text value

-2. Start the App on your UNO Q.
-3. Edit `python/led_text.txt`.
-4. Save the file.
-5. Wait about half a second for the Python side to detect the change.
-6. The LED matrix will update and keep scrolling the new message in a loop.

-SYSU
-```
-

-

+# 开发说明
+
+本文档面向后续维护和扩展 `LED_showtext` 工程时使用，重点说明当前架构、关键扩展点以及修改建议。
+
+## 1. 当前架构
+
+这个 App 使用 UNO Q 的双端模型：
+
+- `python/main.py`
+  运行在 Linux / MPU 侧，负责读取文本输入源并调用 Bridge
+
+- `sketch/sketch.ino`
+  运行在 MCU 侧，负责 LED 矩阵显示
+
+- `Arduino_RouterBridge`
+  负责在两端之间传递文本
+
+当前数据流：
+
+```text
+python/led_text.txt
+    -> python/main.py
+    -> Bridge.call("set_text", text)
+    -> sketch.setText(...)
+    -> renderScrollingText(...)
+    -> UNO Q LED matrix
+```
+
+## 2. 为什么这样设计
+
+这种设计把“输入来源”和“显示实现”分开了：
+
+- Python 端只负责拿到新文本并通知 MCU
+- MCU 端只负责显示
+
+这样做的好处：
+
+- 输入来源可以替换
+- 显示逻辑集中在一处
+- 后续更容易接入 Web UI、传感器、按钮或网络接口
+
+## 3. 当前核心逻辑
+
+### Python 侧
+
+`python/main.py` 的核心函数：
+
+- `read_text_file()`
+  负责从 `led_text.txt` 读取内容
+
+- `send_text_if_changed()`
+  负责比较内容是否变化，只有变化后才调用 `Bridge.call(...)`
+
+- `loop()`
+  每隔 `POLL_INTERVAL_SEC` 秒执行一次轮询
+
+当前策略是“轮询文件变更”，而不是监听文件系统事件。  
+这样实现简单、稳定，也更适合 App Lab 的运行环境。
+
+### Sketch 侧
+
+`sketch/sketch.ino` 的核心函数：
+
+- `renderScrollingText(const String& text)`
+  用 `ArduinoGraphics` 配合 `Arduino_LED_Matrix` 绘制滚动文字
+
+- `setText(String text)`
+  作为 RouterBridge 的 RPC 接口，接收 Python 发送的新文本
+
+- `loop()`
+  持续重播当前滚动动画，使文本循环显示
+
+## 4. 为什么 `loop()` 里要重复调用渲染
+
+如果只在 `setup()` 或 `setText()` 里调用一次滚动逻辑，文本通常只会滚动一轮。  
+为了实现“持续循环滚动”，当前做法是在 `loop()` 中不断重新播放当前文本。
+
+如果后续你发现：
+
+- 循环之间有明显停顿
+- 文本重播不够平滑
+
+那么优化方向应该从 `renderScrollingText()` 的调用策略入手，而不是先改 Python 侧。
+
+## 5. 适合扩展的位置
+
+## 5.1 更换输入源
+
+当前输入源是：
+
+- `python/led_text.txt`
+
+后续可以替换成：
+
+- Web UI 表单输入
+- Python 端固定变量
+- 网络 API 返回内容
+- 串口或 Socket 输入
+- 按钮触发的预设文本
+
+扩展时主要改：
+
+- `python/main.py`
+
+而 `sketch/sketch.ino` 可以保持不变，只要仍然调用：
+
+```python
+Bridge.call("set_text", text)
+```
+
+## 5.2 增加字符过滤
+
+UNO Q 的 LED 矩阵尺寸很小，`Font_5x7` 对复杂字符支持有限。  
+如果后续要增强稳定性，建议在 Python 侧加一层过滤。
+
+建议位置：
+
+- `python/main.py` 中，在 `Bridge.call(...)` 前增加文本清洗函数
+
+典型处理方式：
+
+- 去掉前后空白
+- 限制最大长度
+- 过滤不支持的字符
+- 将连续空格压缩为单个空格
+
+## 5.3 增加多种显示模式
+
+现在只有一种模式：
+
+- 左滚动文本
+
+后续可以扩展成：
+
+- 静态显示短文本
+- 左滚动
+- 右滚动
+- 上下滚动
+- 文本前加图标
+- 文本闪烁
+
+适合修改的位置：
+
+- `sketch/sketch.ino`
+
+建议做法：
+
+- 保留 `setText(...)`
+- 新增 `setMode(...)`
+- 在 MCU 侧维护一个 `currentMode`
+
+这样 Python 端就可以同时调用：
+
+```python
+Bridge.call("set_text", text)
+Bridge.call("set_mode", "scroll_left")
+```
+
+## 5.4 接 Web UI
+
+如果后续你想做浏览器输入文本后立刻显示到 LED 矩阵，建议架构是：
+
+```text
+Web UI
+  -> python/main.py
+  -> Bridge.call("set_text", text)
+  -> sketch/sketch.ino
+```
+
+也就是说：
+
+- Web UI 只和 Python 通信
+- Python 再把文本下发给 MCU
+
+不建议让 Web UI 直接控制每个像素，因为这样会把显示逻辑打散。
+
+## 5.5 接实体按钮
+
+如果你想通过硬件按钮切换预设文本，有两种思路：
+
+### 方案 A：按钮接 MCU
+
+优点：
+
+- 响应快
+- 结构简单
+
+做法：
+
+- 在 `sketch.ino` 里直接读取按钮
+- 按键后修改 `currentText`
+
+### 方案 B：按钮接 Python 侧逻辑
+
+如果按钮事件先进入 Python，则保持当前架构即可：
+
+- Python 处理事件
+- 再调用 `Bridge.call("set_text", text)`
+
+## 6. 当前参数说明
+
+### Python 侧
+
+- `TEXT_FILE`
+  当前文本文件路径
+
+- `POLL_INTERVAL_SEC`
+  文件轮询周期，默认 `0.5`
+
+### Sketch 侧
+
+- `Font_5x7`
+  当前字体
+
+- `matrix.textScrollSpeed(70)`
+  滚动速度
+
+- `SCROLL_LEFT`
+  当前滚动方向
+
+如果要调效果，优先改这几个参数。
+
+## 7. 修改建议
+
+推荐的修改顺序：
+
+1. 先改 `python/led_text.txt` 验证显示链路
+2. 再改 `sketch/sketch.ino` 的速度、字体和滚动方向
+3. 最后再引入新的输入源或新的显示模式
+
+这样更容易定位问题。
+
+## 8. 常见问题
+
+### 8.1 App 启动但不显示文本
+
+优先检查：
+
+- `python/led_text.txt` 是否为空
+- Python App 是否正常运行
+- `Bridge.call("set_text", text)` 是否成功
+
+### 8.2 文本只滚动一次
+
+说明 `loop()` 中没有持续重播当前文本。  
+当前工程已经通过在 `loop()` 中重复调用渲染解决了这个问题。
+
+### 8.3 修改文件后显示没有更新
+
+优先检查：
+
+- 文件是否已保存
+- `POLL_INTERVAL_SEC` 是否太长
+- 新文本是否和旧文本完全相同
+
+### 8.4 文本显示不清楚
+
+原因通常有三个：
+
+- 矩阵尺寸太小
+- 字体不适合
+- 字符本身太复杂
+
+这时建议：
+
+- 尽量使用短文本
+- 使用英文、数字、简单符号
+- 保持 `Font_5x7`
+
+## 9. 建议的下一步扩展
+
+如果要继续把这个工程做成更完整的应用，优先级建议如下：
+
+1. 在 Python 侧加入文本过滤和长度限制
+2. 增加多种显示模式
+3. 接入 Web UI
+4. 增加图标和文本组合显示
+5. 加入按钮或网络输入源
+
+## 10. 结论
+
+当前工程已经具备一个清晰、稳定的最小可扩展结构：
+
+- Python 侧负责接收或生成文本
+- Bridge 负责传输
+- MCU 侧负责最终显示
+
+后续无论是接文件、网页、按钮还是网络接口，都建议保持这个分层方式，不要把所有逻辑堆到单一一端。

`LED_showtext` 是一个面向 **Arduino UNO Q** 的 Arduino App Lab 示例工程，用于在板载 **8 x 13 LED 矩阵** 上循环滚动显示文本。

- `python/main.py` 运行在 Linux / MPU 侧，负责读取文本文件并把变化推送给 MCU

## 工作原理

文本更新链路如下：

1. Python 端读取 `python/led_text.txt`

bridge是什么

Assistant 2026-04-25T07:55:55.121Z

Bridge 可以理解成 UNO Q 上 Python 端和 Arduino Sketch 端之间的通信桥。

在你的项目里，它的作用就是让两边互相“远程调用函数”：

  • Python 调 MCU 例如： python Bridge.call("set_text", text) 这会去调用 sketch.ino 里注册的 set_text。

  • MCU 暴露接口 例如： cpp Bridge.provide_safe("set_text", setText); 这表示把 setText 这个函数开放给 Python 端调用。

所以它本质上不是普通变量，也不是某个“数据桥接文件”，而是 Arduino_RouterBridge 库提供的一个全局通信对象。

你可以把它简单记成：

  • Bridge.call(...) 去调用另一端的方法
  • Bridge.provide(...) / Bridge.provide_safe(...) 把本端方法注册出去给另一端调用
  • Bridge.notify(...) 发通知，不要返回值

在 UNO Q 这种双处理器板子上，它特别重要，因为： - Python 跑在 Linux/MPU 侧 - Sketch 跑在 MCU 侧 - 两边不是同一个运行环境，不能直接互相访问变量 - 所以要靠 Bridge 做 RPC 通信

如果用你刚做完的 LED 项目举例，整条链路是：

  1. Python 读 led_text.txt
  2. Python 调： python Bridge.call("set_text", text)
  3. MCU 侧提前注册了： cpp Bridge.provide_safe("set_text", setText);
  4. 所以 setText() 被执行
  5. LED 矩阵更新显示

一句话说：

Bridge 就是 UNO Q 上 Python 和 Arduino Sketch 互相传消息、互相调函数的桥。

## 工作原理

该示例托管了一个 Web UI，用于协调手机摄像头与开发板之间的连接。视频流通过网络传输到开发板，经过 `video_objectdetection` Brick 处理后，再把识别结果发送回浏览器。检测到目标后，界面会显示目标类别和置信度，例如：`95% potted plant`。

下面从前后端两个部分简要说明这个全栈示例。

### 后端（`python/main.py`）

- **安全和连接**
  - 生成一个随机的 6 位数字密钥 `generate_secret()`，用于保护手机与开发板之间的配对连接。
  - 初始化 `WebSocketCamera(secret=secret, encrypt=True)`，把手机视频流作为远程摄像头输入。

- **App 初始化**
  - `WebUI()`：负责管理前端页面和浏览器通信。
  - `VideoObjectDetection(camera, ...)`：以远程摄像头为输入，对视频画面执行目标检测。

- **事件处理**
  - 监听摄像头状态变化，并把 `connected`、`streaming` 等状态同步到前端页面。
  - 当浏览器连接时，通过 `ui.on_connect(...)` 向前端发送 `secret`、`ip`、`port` 等配对信息，以生成二维码。
  - 通过 `on_detect_all(...)` 把检测结果推送到前端，包括目标类别、置信度和时间戳。

- **控制项**
  - 监听前端发送的 `override_th` 消息，动态修改目标检测的置信度阈值。

### 前端（`assets/index.html + assets/app.js`）

- **配对流程**
  - 通过 Socket.IO 接收后端发来的 `secret`、`ip` 和 `port`。
  - 使用 `qrcode.min.js` 生成二维码，二维码中包含手机连接到开发板所需的配对信息。

- **视频显示**
  - 当手机成功连接后，页面会从二维码视图切换到视频 iframe 视图，显示实时视频流。

- **反馈与控制**
  - **置信度滑块**：用于调整 AI 模型的检测阈值。
  - **视觉反馈**：当检测到某些目标对象（如 `cup`、`cat`）且置信度较高时，界面会显示对应动画和提示文字。
  - **最近检测列表**：显示最近 5 条检测记录及其时间戳。

## 代码理解

当应用运行后并在浏览器中打开时，系统主要执行以下几类工作：

### 1. 提供 Web UI，并处理远程摄像头配对

后端首先生成一个安全密钥，并初始化 `WebSocketCamera`。当浏览器连接后，后端会把这些配对信息发给前端。

```python
def generate_secret() -> str:
  characters = string.digits
  return ''.join(secrets.choice(characters) for _ in range(6))

secret = generate_secret()
ui = WebUI()
camera = WebSocketCamera(secret=secret, encrypt=True)

ui.on_connect(lambda sid: ui.send_message("welcome", {
    "client_name": camera.name,
    "secret": secret,
    "status": camera.status,
    "protocol": camera.protocol,
    "ip": camera.ip,
    "port": camera.port
}))
```

### 2. 处理视频帧并广播检测结果

`VideoObjectDetection` Brick 使用远程摄像头的视频帧做推理。检测到目标后，回调函数会把整理好的结果发给浏览器。

```python
detection = VideoObjectDetection(camera, confidence=0.5, debounce_sec=0.0)

def send_detections_to_ui(detections: dict):
  for key, values in detections.items():
    for value in values:
      entry = {
        "content": key,
        "confidence": value.get("confidence"),
        "timestamp": datetime.now(UTC).isoformat()
      }
      ui.send_message("detection", entry)

detection.on_detect_all(send_detections_to_ui)
```

### 3. 在前端生成二维码

前端 `app.js` 会等待 `welcome` 消息，然后生成二维码，用来把手机和开发板配对起来。

```javascript
socket.on('welcome', async (message) => {
    webcamState.secret = message.secret;
    webcamState.protocol = message.protocol;
    webcamState.ip = message.ip;
    webcamState.port = message.port;
    updateDisplay();
});

function updateDisplay() {
    if (webcamState.status != "connected") {
        if (webcamState.secret) {
            generateQRCode(webcamState.secret, webcamState.protocol, webcamState.ip, webcamState.port);
        }
    }
}
```

### 4. 运行 App 主循环

最后，后端通过：

```python
App.run()
```

维持整个应用运行，协调手机、AI 模型和浏览器之间的网络通信。
