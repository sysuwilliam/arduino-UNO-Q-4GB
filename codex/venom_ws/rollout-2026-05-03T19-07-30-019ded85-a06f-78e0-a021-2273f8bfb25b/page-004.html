你现在有两种调法：临时动态调参，或者永久改 YAML。

方式 1：运行时临时调参

仿真正在跑的时候，另开一个终端：

cd /home/william/venom_ws/src/venom_vnv/simulation/venom_nav_simulation

source /opt/ros/humble/setup.bash
source /home/william/venom_ws/install/setup.bash
source install/setup.bash

先看 TEB 参数：

ros2 param list /controller_server | grep FollowPath

查看当前值：

ros2 param get /controller_server FollowPath.max_vel_x
ros2 param get /controller_server FollowPath.max_vel_y
ros2 param get /controller_server FollowPath.max_vel_theta
ros2 param get /controller_server FollowPath.min_obstacle_dist

临时修改：

ros2 param set /controller_server FollowPath.max_vel_x 1.5
ros2 param set /controller_server FollowPath.max_vel_y 1.5
ros2 param set /controller_server FollowPath.max_vel_theta 3.0
ros2 param set /controller_server FollowPath.min_obstacle_dist 0.35
ros2 param set /controller_server FollowPath.inflation_dist 0.8

然后直接在 RViz2 里重新发目标点，看局部轨迹和机器人运动变化。

这些改动重启仿真后会丢失。

方式 2：永久改配置文件

改这个文件：

/home/william/venom_ws/src/venom_vnv/simulation/venom_nav_simulation/src/rm_nav_bringup/config/simulation/nav2_params_sim.yaml

找到：

controller_server:
  ros__parameters:
    FollowPath:
      plugin: teb_local_planner::TebLocalPlannerROS

下面就是 TEB 参数，例如：

max_vel_x: 3.0
max_vel_x_backwards: 3.0
max_vel_theta: 6.0
acc_lim_x: 4.0
acc_lim_theta: 6.0
max_vel_y: 3.0
acc_lim_y: 4.0
min_obstacle_dist: 0.25
inflation_dist: 0.6
weight_obstacle: 100.0
weight_optimaltime: 0.1

改完后重启仿真即可生效。

常用调参方向：

机器人太快：
  降 max_vel_x / max_vel_y / max_vel_theta

加减速太猛：
  降 acc_lim_x / acc_lim_y / acc_lim_theta

离障碍物太近：
  增 min_obstacle_dist / inflation_dist / weight_obstacle

路径太绕或太保守：
  降 weight_obstacle 或 inflation_dist

想更快到目标：
  增 weight_optimaltime，适当提高 max_vel_x

局部轨迹抖动：
  增 dt_ref，降低速度/加速度，适当提高 obstacle 距离

建议流程：

  1. 先用 ros2 param set 动态试。
  2. 在 RViz2 连续发几个目标点验证。
  3. 确认参数合适后，写回 nav2_params_sim.yaml。
  4. 重启仿真确认效果。

是的，大体流程就是：先在仿真里调好一组参数，再迁移到实车配置里做低速验证。但不能理解成“仿真调好就一定直接适用于实车”，只能作为实车初值。

原因是仿真和实车虽然用的是同一套 TEB 代码，但环境不同。

你现在的 TEB 代码来自这里：

/home/william/venom_ws/src/venom_vnv/planning/navigation/venom_teb_controller/venom_teb_controller

ROS 包名是：

teb_local_planner

仿真 Nav2 配置里使用的是：

plugin: teb_local_planner::TebLocalPlannerROS

所以仿真和实车如果也配置成这个 plugin，那么用的就是同一套项目里的 TEB 插件。

为什么仿真里也有一份参数表？因为仿真是一个独立工作区，有自己的 bringup：

simulation/venom_nav_simulation

它需要自己能启动 Gazebo、LIO、slam_toolbox、Nav2，所以它有自己的 Nav2 参数文件：

simulation/venom_nav_simulation/src/rm_nav_bringup/config/simulation/nav2_params_sim.yaml

这份参数是给“仿真场景”用的。

实车则由主项目 bringup 启动，参数应该在：

venom_bringup/config/<robot_type>/nav2_params.yaml

例如：

venom_bringup/config/scout_mini/nav2_params.yaml
venom_bringup/config/sentry/nav2_params.yaml

可以这样理解：

TEB 源码：
  同一套

仿真参数：
  给 Gazebo + 仿真雷达 + 仿真底盘 + 仿真地图用

实车参数：
  给真实底盘 + 真实雷达 + 真实 TF + 真实延迟/摩擦/控制响应用

仿真参数不能完全等同于实车参数，因为实车有这些差异：

  • 真实底盘速度响应有延迟
  • 真实轮胎/地面摩擦不同
  • 雷达噪声、盲区、点云密度不同
  • TF 和外参可能有误差
  • 控制话题到下位机还有串口/CAN 延迟
  • 实车安全距离要求更保守
  • 真实机器人尺寸和 footprint 必须更准确

所以推荐流程是：

  1. 在仿真里调出一组能稳定导航的 TEB 参数
  2. 把核心参数迁移到实车 venom_bringup/config/<robot_type>/nav2_params.yaml
  3. 实车先降低速度和加速度
  4. 在空旷场地验证
  5. 再逐步提高速度、缩小安全距离或优化权重

迁移时优先迁移这些参数：

max_vel_x
max_vel_y
max_vel_theta
acc_lim_x
acc_lim_y
acc_lim_theta
min_obstacle_dist
inflation_dist
dt_ref
dt_hysteresis
weight_obstacle
weight_inflation
weight_optimaltime
weight_kinematics_nh
weight_kinematics_forward_drive

一句话：仿真和实车可以共用同一套 TEB 算法代码，但应该保留两套参数文件；仿真调参结果是实车调参的起点，不是最终答案。
