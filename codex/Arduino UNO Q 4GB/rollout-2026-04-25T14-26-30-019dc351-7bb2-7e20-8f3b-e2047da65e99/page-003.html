+# 😀 LED_showtext
+
+`LED_showtext` is an Arduino App Lab example for **Arduino UNO Q** that scrolls
+text across the onboard **8 x 13 LED matrix**.
+
+The App uses a split architecture:
+
+- `python/main.py` runs on the Linux side of UNO Q and watches a text file.
+- `sketch/sketch.ino` runs on the MCU side and renders scrolling text on the LED matrix.
+- The two sides communicate through `Arduino_RouterBridge`.
+
+## How It Works
+
+The text update pipeline is:
+
+1. Python reads `python/led_text.txt`.
+2. If the file content changed, Python calls `Bridge.call("set_text", text)`.
+3. The sketch receives the new string through `setText(...)`.
+4. The sketch redraws the LED matrix and keeps replaying the scroll animation in `loop()`.
+
+This design avoids hardcoding the text in the sketch and makes updates possible
+without editing or recompiling the Arduino code each time.
+
+## Project Structure
+
+```text
+led_showtext/
+├── app.yaml                 # App metadata
+├── python/
+│   ├── main.py              # Linux-side controller
+│   └── led_text.txt         # Source text to display
+└── sketch/
+    ├── sketch.ino           # MCU-side LED matrix rendering
+    └── sketch.yaml          # Sketch platform and library dependencies
+```
+
+## Main Files
+
+### `python/main.py`
+
+Responsibilities:
+
+- Poll `python/led_text.txt`
+- Detect when the content changes
+- Send the updated string to the sketch using RouterBridge
+
+Important details:
+
+- Polling interval is controlled by `POLL_INTERVAL_SEC`
+- Empty text is ignored
+- Previously sent text is cached so unchanged content is not resent
+
+### `sketch/sketch.ino`
+
+Responsibilities:
+
+- Initialize the UNO Q LED matrix
+- Register the `set_text` RPC endpoint
+- Render scrolling text with `ArduinoGraphics`
+- Replay the current scroll animation continuously
+
+Important details:
+
+- Uses `Font_5x7`, which fits the 8x13 matrix reasonably well
+- Uses `SCROLL_LEFT` for leftward scrolling
+- Starts with a blank display until Python pushes the first text value
+
+## How To Use
+
+1. Open the App in Arduino App Lab.
+2. Start the App on your UNO Q.
+3. Edit `python/led_text.txt`.
+4. Save the file.
+5. Wait about half a second for the Python side to detect the change.
+6. The LED matrix will update and keep scrolling the new message in a loop.
+
+Example:
+
+```text
+SYSU
+```
+
+or:
+
+```text
+Hello UNO Q
+```
+
+## Dependencies
+
+The sketch depends on:
+
+- `Arduino_RouterBridge`
+- `Arduino_LED_Matrix`
+- `ArduinoGraphics`
+
+The Python side depends on Arduino App Lab's built-in `arduino.app_utils`.
+
+## Notes
+
+- The UNO Q LED matrix is only **8 x 13**, so long text is best shown as scrolling text.
+- Very complex characters may not render well on this matrix size.
+- If the matrix stays blank, first check whether `python/led_text.txt` contains non-empty text.
+
+## Communication Summary
+
+- Python -> MCU method name: `set_text`
+- Python call: `Bridge.call("set_text", text)`
+- Sketch registration: `Bridge.provide_safe("set_text", setText)`
+
+## Files To Edit Most Often
+
+- Change displayed text: `python/led_text.txt`
+- Change polling speed: `python/main.py`
+- Change scroll speed, font, or rendering behavior: `sketch/sketch.ino`

# Polling interval for checking whether the text file content changed.
POLL_INTERVAL_SEC = 0.5

# Cache the last successfully pushed text so we only notify the MCU when needed.
last_sent_text = None

print("LED matrix text app started.")
print(f"Edit {TEXT_FILE} to update the scrolling text.")


def read_text_file() -> str:
    """Read the current text from disk.

    Returns an empty string if the file does not exist or if the content is blank
    after stripping whitespace.
    """
    try:
        text = TEXT_FILE.read_text(encoding="utf-8").strip()
    except FileNotFoundError:
        return ""

    return text


def send_text_if_changed() -> None:
    """Push updated text to the MCU only when the file content actually changes."""
    global last_sent_text

    text = read_text_file()
    if not text or text == last_sent_text:
        return

    # The sketch exposes a RouterBridge RPC named "set_text".
    # Once the call succeeds, the MCU redraws the scrolling message immediately.
    ok = Bridge.call("set_text", text)
    if ok:
        last_sent_text = text
        print(f"Updated LED text: {text}")
    else:
        print(f"Failed to update LED text: {text}")


def loop():
    """Main App loop: poll the text file and forward updates to the sketch."""
    send_text_if_changed()
    time.sleep(POLL_INTERVAL_SEC)


App.run(user_loop=loop)

  matrix.beginDraw();
  matrix.background(0x000000);
  matrix.clear();

# 😀 LED_showtext

`LED_showtext` is an Arduino App Lab example for **Arduino UNO Q** that scrolls
text across the onboard **8 x 13 LED matrix**.

The App uses a split architecture:

- `python/main.py` runs on the Linux side of UNO Q and watches a text file.
- `sketch/sketch.ino` runs on the MCU side and renders scrolling text on the LED matrix.
- The two sides communicate through `Arduino_RouterBridge`.

## How It Works

The text update pipeline is:

1. Python reads `python/led_text.txt`.
2. If the file content changed, Python calls `Bridge.call("set_text", text)`.
3. The sketch receives the new string through `setText(...)`.
4. The sketch redraws the LED matrix and keeps replaying the scroll animation in `loop()`.

This design avoids hardcoding the text in the sketch and makes updates possible
without editing or recompiling the Arduino code each time.

## Project Structure

```text
led_showtext/
├── app.yaml                 # App metadata
├── python/
│   ├── main.py              # Linux-side controller
│   └── led_text.txt         # Source text to display
└── sketch/
    ├── sketch.ino           # MCU-side LED matrix rendering
    └── sketch.yaml          # Sketch platform and library dependencies
```

## Main Files

### `python/main.py`

Responsibilities:

- Poll `python/led_text.txt`
- Detect when the content changes
- Send the updated string to the sketch using RouterBridge

Important details:

- Polling interval is controlled by `POLL_INTERVAL_SEC`
- Empty text is ignored
- Previously sent text is cached so unchanged content is not resent

### `sketch/sketch.ino`

Responsibilities:

- Initialize the UNO Q LED matrix
- Register the `set_text` RPC endpoint
- Render scrolling text with `ArduinoGraphics`
- Replay the current scroll animation continuously

Important details:

- Uses `Font_5x7`, which fits the 8x13 matrix reasonably well
- Uses `SCROLL_LEFT` for leftward scrolling
- Starts with a blank display until Python pushes the first text value

## How To Use

1. Open the App in Arduino App Lab.
2. Start the App on your UNO Q.
3. Edit `python/led_text.txt`.
4. Save the file.
5. Wait about half a second for the Python side to detect the change.
6. The LED matrix will update and keep scrolling the new message in a loop.

Example:

```text
SYSU
```

or:

```text
Hello UNO Q
```

## Dependencies

The sketch depends on:

- `Arduino_RouterBridge`
- `Arduino_LED_Matrix`
- `ArduinoGraphics`

The Python side depends on Arduino App Lab's built-in `arduino.app_utils`.

## Notes

- The UNO Q LED matrix is only **8 x 13**, so long text is best shown as scrolling text.
- Very complex characters may not render well on this matrix size.
- If the matrix stays blank, first check whether `python/led_text.txt` contains non-empty text.

## Communication Summary

- Python -> MCU method name: `set_text`
- Python call: `Bridge.call("set_text", text)`
- Sketch registration: `Bridge.provide_safe("set_text", setText)`

- Change displayed text: `python/led_text.txt`
- Change polling speed: `python/main.py`
- Change scroll speed, font, or rendering behavior: `sketch/sketch.ino`
