我浏览了一遍项目。它是一个 ROS 2 Humble 的 colcon 工作区，根目录 /home/william/venom_ws 下面有 build/、install/、src/；真正的 Git 仓库在 src/venom_vnv，当前分支是 master，跟踪 origin/master，工作区干净。

核心结构是 README 里描述的七层机器人平台：

  • driver/：Livox、相机、底盘、机械臂、PX4、串口等驱动入口
  • perception/：自瞄、YOLO、二维码/条码识别
  • localization/：Point-LIO、Fast-LIO、rf2o、重定位预留
  • planning/：导航规划、TEB controller、机械臂规划
  • mission/：任务层预留目录
  • venom_bringup/：系统启动、机器人 bringup、当前过渡期任务控制
  • venom_robot_description/：TF、URDF、机器人描述
  • simulation/venom_nav_simulation/：仿真环境

当前本地实际可被顶层 colcon 识别的主要 Python ROS 包有三个：

  1. venom_bringup 系统启动包，包含 Mid360、Point-LIO、自瞄、Scout Mini、Sentry、PX4、Nav2/任务导航相关 launch。入口脚本有 multi_waypoint_commander。

  2. venom_mission_commander 独立任务编排包。默认 mock 模式，不依赖真实 Nav2/action server，会按 YAML 里的 waypoint 顺序执行“导航到点 -> 执行任务插件”。主入口是 mission_commander.py，任务插件在 task_plugins.py。

  3. venom_robot_description TF 发布包，从 YAML 加载静态/动态 TF。实现入口是 dynamic_tf_publisher.py。

几个常用命令：

cd /home/william/venom_ws
source install/setup.bash

ros2 launch venom_bringup mid360_rviz.launch.py
ros2 launch venom_bringup health_aware_navigation.launch.py

ros2 launch venom_mission_commander mission_commander.launch.py use_nav:=false
ros2 launch venom_robot_description scout_mini_description.launch.py

我没有运行构建或测试，只做了静态浏览。一个明显注意点：venom_robot_description 直接依赖 venom_serial_driver.msg.RobotStatus，如果驱动包/消息没有正确构建或 source，TF 节点会导入失败。另一个注意点是 README 里的大平台目录都存在，但当前主要活跃实现集中在 venom_bringup、venom_mission_commander 和 venom_robot_description。

推荐先用 Docker 方式，因为仿真依赖比较重，文档也说明这个仿真工作区不建议直接并进主部署工作区。

方式一：Docker 启动

在主仓库根目录执行：

cd /home/william/venom_ws/src/venom_vnv

make build
make up
make shell

进入容器后执行：

cd /ros_ws
source /opt/ros/humble/setup.bash

rosdep install -r --from-paths src --ignore-src --rosdistro humble -y

colcon build --cmake-args \
  -DCMAKE_BUILD_TYPE=Release \
  -DROS_EDITION=ROS2 \
  -DHUMBLE_ROS=humble

source install/setup.bash

然后启动仿真导航：

ros2 launch rm_nav_bringup bringup_sim.launch.py \
  world:=RMUL \
  mode:=nav \
  lio:=pointlio \
  localization:=slam_toolbox \
  lio_rviz:=False \
  nav_rviz:=True

文档也提供了封装命令，可以替代容器内的 rosdep 和 colcon：

cd /home/william/venom_ws/src/venom_vnv
make rosdep
make colcon

方式二：本机直接启动

如果你本机已经有 ROS 2 Humble、Nav2、Gazebo/Ignition、相关仿真依赖，可以直接跑独立仿真工作区：

cd /home/william/venom_ws/src/venom_vnv/simulation/venom_nav_simulation

rosdep install -r --from-paths src --ignore-src --rosdistro $ROS_DISTRO -y

colcon build --symlink-install

source install/setup.bash

ros2 launch rm_nav_bringup bringup_sim.launch.py \
  world:=RMUL \
  mode:=nav \
  lio:=pointlio \
  localization:=slam_toolbox \
  lio_rviz:=False \
  nav_rviz:=True

参数含义：

  • world:=RMUL：加载 RMUL 仿真世界
  • mode:=nav：导航模式
  • lio:=pointlio：使用 Point-LIO
  • localization:=slam_toolbox：使用 slam_toolbox 做定位/建图链路
  • lio_rviz:=False：不单独打开 LIO RViz
  • nav_rviz:=True：打开 Nav2 RViz

启动成功后，通常会看到 Gazebo/Ignition 仿真场景和 RViz。先在 RViz 里用 2D Goal Pose 发一个目标点，验证 Nav2 是否能规划和移动。

IP address: 192.168.1.50

MID360 的雷达 IP 通常是：

192.168.1.1xx

xx 是雷达序列号后两位。比如序列号末两位是 33，雷达 IP 就可能是：

192.168.1.133

图形界面配置

  1. 插上连接 MID360 的网线。
  2. 点击 Ubuntu 右上角/左上角网络图标。
  3. 进入 Settings / 设置。
  4. 进入 Network / 网络。
  5. 找到 Wired / 有线，点齿轮图标。
  6. 打开 IPv4。
  7. IPv4 Method 选择 Manual。
  8. 填入：
Address: 192.168.1.50
Netmask: 255.255.255.0
Gateway: 192.168.1.1
DNS: 可以留空
  1. 保存。
  2. 关闭再打开这个有线网络，或者拔插网线。

ip addr

你应该能在有线网卡上看到类似：

inet 192.168.1.50/24

然后 ping 雷达，例如雷达 IP 是 192.168.1.133：

ping 192.168.1.133

ip route

有线网卡名: enp3s0
本机 IP:   192.168.1.50
雷达 IP:   192.168.1.133

ip route get 192.168.1.133

找不到 Wired 一般有几种情况：没插网线、网卡没被系统识别、Ubuntu 语言显示成“有线”、或者你的连接叫别的名字。

先用命令确认网卡名：

ip link

看有没有类似这些名字：

enp3s0
eno1
enx...
eth0

有线网卡通常不是 lo，也不是 wlan0 / wlp...。

再看 NetworkManager 识别到的设备：

nmcli device status

你会看到类似：

DEVICE   TYPE      STATE         CONNECTION
enp3s0   ethernet  disconnected  --
wlp2s0   wifi      connected     xxx
lo       loopback  unmanaged     lo

如果有 TYPE ethernet，那个就是有线网卡。假设它叫 enp3s0，可以不用图形界面，直接命令配置静态 IP：

sudo nmcli con add type ethernet ifname enp3s0 con-name mid360 \
  ipv4.addresses 192.168.1.50/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.method manual

启动这个连接：

sudo nmcli con up mid360

检查：

ip addr show enp3s0

如果你已经有一个有线连接，不想新建，可以查连接名：

nmcli con show

然后修改现有连接。假设连接名叫 Wired connection 1：

sudo nmcli con mod "Wired connection 1" \
  ipv4.addresses 192.168.1.50/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.method manual

sudo nmcli con up "Wired connection 1"

如果 nmcli device status 里面完全没有 ethernet，那说明系统没看到有线网卡。检查：

  1. 如果电脑本身有网口，插上网线后看内核日志：

enp3s0

eth0

sudo nmcli con add type ethernet ifname enx123456 con-name mid360 \

  ipv4.gateway 192.168.1.1 \
  ipv4.method manual

sudo nmcli con up mid360
