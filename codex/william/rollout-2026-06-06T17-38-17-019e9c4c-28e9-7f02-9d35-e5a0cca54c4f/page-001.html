根据 Arduino 文档，不是把模型文件手动上传到 App 里，而是通过 App Lab 和 Edge Impulse 的账号集成同步回来。

你现在模型已经在网页里训练好后，按这个流程做：

  1. 回到 Arduino App Lab。
  2. 打开你要使用模型的 App。
  3. 确认 App 里已经添加了对应的 Brick，例如图像识别要用 Video Object Detection Brick。
  4. 进入这个 Brick 的 AI models 标签页。
  5. 训练好的自定义模型应该会出现在可用模型列表里。
  6. 点击模型旁边的 Install，等待它构建并安装到 Arduino UNO Q。
  7. 安装完成后，打开 Brick 的 Configuration，选择你的新模型。
  8. 运行 App，之后这个 Brick 就会使用你的自定义模型。

文档里的关键点是：训练完成后“回到 Arduino App Lab，你的新模型会出现在 Brick 的可用模型列表中”，然后点击 Install 安装到 UNO Q，再在 Brick 配置里选择它。来源：Arduino 文档的 Custom AI Model Usage 部分：
https://docs.arduino.cc/software/app-lab/tutorials/ai-models/

如果你回到 App Lab 后没有看到模型，优先检查这几个点：

  • 是否用的是同一个 Arduino / Edge Impulse 账号。
  • 是否是从 App Lab 里的 Train new AI model 入口跳转到 Edge Impulse 的。
  • 模型类型是否匹配 Brick，例如 Object Detection 模型要配 Video Object Detection Brick。
  • 训练是否已经完成，并且模型在 Edge Impulse 里测试通过。
  • 关闭再重新打开 App 或刷新 App Lab 的 Brick 页面。

另外，Edge Impulse 可以导出 .eim 文件，但按这篇文档的说法，.eim 手动导出主要是用于在 Arduino App Lab 之外的 C++ 或 Python 项目里实验；在 App Lab 里通常走 AI models 列表 -> Install -> Configuration 选择模型 这条路径。

这篇 Edge Impulse 文档讲的是 不通过 Arduino App Lab 的另一条部署路线：直接把 UNO Q 当作 Linux 设备连接到 Edge Impulse，然后用命令行下载安装到板子上运行。

也就是说你现在有两种方式：

方式 A：在 Arduino App Lab 里用模型

适合你前面说的“导入 app 中”。

流程是：

  1. 在 App Lab 里打开你的 App。
  2. 找到对应的 AI Brick，例如 Video Object Detection Brick。
  3. 进入 Brick 的 AI models。
  4. 找到你训练好的模型。
  5. 点 Install。
  6. 安装完成后，在 Brick 的 Configuration 里选择这个模型。
  7. 运行 App。

这个方式不需要你手动下载 .eim 文件，也不需要 SSH 到 UNO Q。

方式 B：直接在 UNO Q 上运行 Edge Impulse 模型

这是你发的 Edge Impulse 文档里的方式。适合你想绕过 App Lab，用命令行在 UNO Q 上直接跑模型。

大致流程是：

  1. 给 UNO Q 连网，并开启 SSH 或接屏幕进入终端。
  2. 在 UNO Q 上安装 Edge Impulse 依赖：
sudo apt update
curl -sL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt install -y gcc g++ make build-essential nodejs sox gstreamer1.0-tools gstreamer1.0-plugins-good gstreamer1.0-plugins-base gstreamer1.0-plugins-base-apps
sudo npm install edge-impulse-linux -g --unsafe-perm
  1. 连接 Edge Impulse 项目：
edge-impulse-linux

它会让你登录 Edge Impulse，并选择项目。

  1. 运行模型：
edge-impulse-linux-runner

这个命令会自动编译、下载模型到 UNO Q，然后开始推理。

官方文档来源：
https://docs.edgeimpulse.com/hardware/boards/arduino-uno-q

关键区别是：

目标 用哪种方式
想在 Arduino App Lab 做的 App 里使用模型 用 App Lab 的 AI models -> Install -> Configuration
想在 UNO Q Linux 系统里直接测试模型 用 edge-impulse-linux-runner
想自己写 Python / C++ 程序调用模型 用 Edge Impulse Linux SDK 或导出的 Linux .eim

所以，如果你的目标仍然是“导入 App Lab 的 App 中”，不要按这篇 Edge Impulse 文档去跑 edge-impulse-linux-runner。那是独立运行模型，不是把模型放进 App Lab 的 Brick 里。

Assistant 2026-06-06T09:43:53.404Z

可以从 Edge Impulse 网页端 和 Arduino App Lab 两边确认。

在 Edge Impulse 确认

  1. 打开你的 Edge Impulse 项目。
  2. 进入左侧的 Impulse design。
  3. 确认里面已经有完整流程，例如：
  4. 输入数据类型，比如 image / audio / sensor
  5. Processing block
  6. Learning block，例如 object detection / classification
  7. 进入左侧 Model testing。
  8. 如果你能看到测试结果、准确率、混淆矩阵或检测结果，说明模型已经训练过。
  9. 再进入 Dashboard 或 Deployment。
  10. 如果页面提示模型可以部署，或者可以生成 Linux / .eim / Arduino library 等部署包，说明模型已经训练完成。

最直接的判断是：
Model testing 页面能跑出结果，Deployment 页面能构建模型。

在 Arduino App Lab 确认

如果你是从 App Lab 的 Train new AI model 跳转到 Edge Impulse 训练的：

  1. 回到 Arduino App Lab。
  2. 打开你的 App。
  3. 选中对应的 AI Brick，例如 Video Object Detection Brick。
  4. 打开 Brick 的 AI models 页面。
  5. 看列表里是否出现你训练的模型。
  6. 如果出现并且有 Install 按钮，就说明 App Lab 识别到了这个模型。

注意：模型必须和 Brick 类型匹配。比如：

训练的模型 App Lab 中对应 Brick
图像分类 Image Classification 相关 Brick
目标检测 Video Object Detection Brick
音频分类 Audio Classification 相关 Brick
传感器分类 Sensor / IMU 相关 Brick

如果你在 Edge Impulse 里不确定有没有训练成功

看这几个地方：

  • Impulse design > Image 或类似训练页面里是否点过 Start training
  • 是否有训练完成后的准确率，例如 accuracy / F1 score / loss
  • Model testing 是否可以点击 Classify all 或显示测试结果
  • Deployment 是否可以成功 build
  • 项目 Dashboard 是否显示最近训练过的 model / impulse

如果 App Lab 里看不到模型

常见原因是：

  • Edge Impulse 和 Arduino App Lab 不是同一个账号或没有正确绑定。
  • 不是从 App Lab 的训练入口创建的模型。
  • 训练还没完成。
  • 模型类型和当前 Brick 不匹配。
  • App Lab 页面还没刷新。
  • Edge Impulse 项目没有部署到兼容 UNO Q / App Lab 的格式。

简单判断路径：

Edge Impulse 能 Model testing -> 说明模型训练过
Edge Impulse 能 Deployment build -> 说明模型可部署
App Lab 的 AI models 里能看到 -> 说明可以导入当前 App

如果你愿意，可以把你 Edge Impulse 左侧菜单里目前能看到的页面名称，或者 Dashboard / Model testing / Deployment 页面截图发我，我可以帮你判断现在卡在哪一步。

这个提示的意思是：你的 Edge Impulse 项目里还没有完成完整训练，所以现在不能做 Model testing / Validate，也还不能导入 App Lab 使用。

你需要按左侧导航栏把训练流程补完。一般步骤如下：

  1. Data acquisition
  2. 确认已经上传或采集了数据。
  3. 数据要有标签，例如 person、object、normal、warning 等。

  4. 如果是图像目标检测，还要确认图片里已经画了 bounding box。

  5. Impulse design

  6. 进入 Create impulse。
  7. 配好输入大小和处理模块。
  8. 例如图像模型通常是：
    • Image
    • Classification 或 Object Detection

  9. 配好后点击 Save impulse。

  10. Processing block

  11. 如果你选的是 Image，左侧通常会出现 Image 页面。
  12. 进入它。
  13. 点击 Save parameters。

  14. 然后点击 Generate features。

  15. Learning block

  16. 进入你的训练页面，例如：
    • Classifier
    • Object detection
    • Transfer learning
  17. 设置训练参数。
  18. 点击 Start training。

  19. 等训练完成，页面应该显示 accuracy / loss / F1 score 等结果。

  20. Model testing

  21. 回到 Model testing。
  22. 这时再点击测试/验证，应该就不会再出现 “not fully trained”。

也就是说，Edge Impulse 里不是只上传数据就算有模型。必须完成：

Create impulse
-> Save parameters
-> Generate features
-> Start training
-> Model testing

如果你是做 Arduino App Lab 的视觉模型，最常见漏掉的是：

  • 只创建了 impulse，但没有点 Generate features。
  • 只生成了 features，但没有点 Start training。
  • 图片上传了，但没有标注标签或 bounding box。
  • 选择了 Object Detection，但数据不是目标检测格式。
  • 修改过 Create impulse 后，没有重新生成 features 和重新训练。

你可以先检查左侧导航栏：
如果某个项目旁边还有感叹号、灰色状态、或者提示未完成，就从那里继续配置。完成训练后，再回到 App Lab 的 AI Brick 里看模型是否出现。

App.run()这个什么意思

Assistant 2026-06-06T09:58:44.355Z

这段代码是在 Arduino App Lab 里使用一个“视频目标检测 Brick”，打开摄像头/视频流后持续识别画面里的物体；一旦检测到对象，就把检测结果打印出来。

逐段解释：

from arduino.app_utils import App
from arduino.app_bricks.video_objectdetection import VideoObjectDetection

导入 App Lab 运行所需的模块：

  • App：负责启动 App Lab 应用。
  • VideoObjectDetection：视频目标检测功能，也就是识别摄像头画面中的物体。
detection_stream = VideoObjectDetection(confidence=0.5, debounce_sec=0.0)

创建一个目标检测对象。

参数含义：

  • confidence=0.5：只接受置信度大于等于 0.5 的检测结果，也就是 50% 以上把握 的识别结果。
  • debounce_sec=0.0：去抖时间为 0 秒。也就是说，只要检测到对象，就可以立刻触发回调，不做延迟过滤。
def print_detections(detections: dict):

定义一个函数，用来处理检测结果。
这个函数会在检测到物体时被调用。

detections 大概是一个字典，结构类似：

{
    "person": [
        {"confidence": 0.91, "x": 100, "y": 80, "width": 50, "height": 120}
    ],
    "cup": [
        {"confidence": 0.76, "x": 220, "y": 130, "width": 40, "height": 60}
    ]
}

也就是：

  • key 是识别出的类别名称，比如 "person"、"cup"。
  • value 是这个类别对应的检测列表，因为同一画面里可能有多个同类物体。
for key, value in detections.items():

遍历每一种检测到的类别。

比如：

key = "person"
value = [{"confidence": 0.91, ...}]

for detection in value:

遍历这一类里的每一个检测框。

例如画面里有 2 个人，就会循环 2 次。

entry = {
    "content": key,
    "confidence": f"{round(detection.get('confidence', 0) * 100)} %"
}

把检测结果整理成一个新的字典：

{
    "content": "person",
    "confidence": "91 %"
}

其中：

  • content：识别到的物体类别。
  • confidence：置信度百分比。
  • detection.get('confidence', 0)：从检测结果里取 confidence，如果没有这个字段就用 0。
  • * 100：把 0.91 转成 91。
  • round(...)：四舍五入。
  • f"... %"：格式化成字符串，例如 "91 %"。
print(entry)

把结果打印到控制台。

detection_stream.on_detect_all(print_detections)

注册回调函数。
意思是：当检测到所有对象时，调用 print_detections 这个函数处理结果。

App.run()

启动 App。
没有这一行，App Lab 不会真正开始运行检测。

所以整段代码可以理解为：

启动视频目标检测
如果画面中识别到物体
就把物体名称和置信度打印出来

例如运行时可能输出：

{'content': 'person', 'confidence': '93 %'}
{'content': 'cup', 'confidence': '78 %'}

如果你训练的是自己的模型，比如识别 apple、banana、bottle，那么这里的 content 就会显示你的模型标签名称。
