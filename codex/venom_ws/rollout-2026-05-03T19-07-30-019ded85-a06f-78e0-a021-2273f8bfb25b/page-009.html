map
└── odom
    └── base_link
        ├── livox_frame
        ├── imu_link
        ├── wheel_1
        ├── wheel_2
        ├── wheel_3
        └── wheel_4

如果他 TF 树断了，常见断点是：

map -> odom 没有
odom -> base_link 没有
base_link -> livox_frame 没有

map -> odom 缺：
  slam_toolbox / AMCL / ICP 没起来，或 localization 配置错

odom -> base_link 缺：
  Point-LIO 没正常输出 odom/TF，或 LIO 没收到 /livox/lidar、/livox/imu

base_link -> livox_frame 缺：
  robot_state_publisher 没起来，URDF/xacro 没发布，或 robot_description 异常

你先在你机器上跑：

ros2 run tf2_ros tf2_echo map odom
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo base_link livox_frame

如果这三条都有持续输出，你的 TF 主链路就是通的。

tf树断了会有什么问题

Assistant 2026-05-04T03:55:04.511Z

TF 树断了，ROS 里很多模块就不知道“不同坐标系之间怎么换算”，导航基本会出各种异常。

在你这个仿真里，正常主链路应该类似：

map -> odom -> base_link -> livox_frame

如果断了，会有这些问题。

1. RViz 显示异常

常见现象：

No transform from [xxx] to [map]
Frame [xxx] does not exist
Message Filter dropping message

表现为：

  • 点云不显示
  • LaserScan 不显示
  • 地图和机器人不重合
  • 机器人模型飘走
  • 轨迹显示断掉
  • Fixed Frame 设成 map 后很多东西红色报错

2. Nav2 无法导航

Nav2 需要知道：

map -> odom
odom -> base_link
base_link -> lidar

断了以后会出现：

Timed out waiting for transform
Could not transform from base_link to map
Invalid frame ID

表现为：

  • Nav2 lifecycle 起不来
  • costmap 不更新
  • planner 规划失败
  • controller 不发速度
  • 发目标点后没反应
  • 一直卡在 waiting for transform

3. 定位/建图异常

比如：

odom -> base_link

断了，说明里程计或 LIO 没正常发布机器人位姿。

结果是：

  • 机器人位置不更新
  • slam_toolbox 收到 scan 但无法定位
  • map 和 odom 接不上
  • 轨迹不动或乱跳

4. 传感器数据用不了

如果：

base_link -> livox_frame

断了，系统不知道雷达安装在车体哪里。

结果是：

  • 点云无法转到车体/地图坐标
  • 障碍物位置错误
  • costmap 障碍物乱飞
  • 导航误判障碍物
  • 机器人可能绕不过去或撞障碍

5. 控制方向可能错

如果 base_link、base_link_fake、odom 关系错，控制器可能认为车头方向和实际不同。

表现为：

  • 车横着走
  • 原地乱转
  • 朝反方向走
